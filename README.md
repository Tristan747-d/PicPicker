# PicPicker · Vision 智能选片

一个 macOS 终端 TUI 程序：递归扫描一个文件夹（含所有子文件夹）里的照片，用 **Apple Vision** 找出内容重复/连拍的照片并分组，在每组里挑出最好的一张（美观、曝光、对焦、人像质量），把整组按 `组号-原文件名` 重命名，并给最佳照片打上 Finder **绿色标签**。

选片之前先做预处理：

- **红标（不参与选片）**：ISO 大于 16000 的 JPG；极端过曝 / 极端欠曝；文档或截图；地平倾斜超过 35°；**死白 / 死黑**（整块区域拉不回来，见下）。
- **黄标（仍参与选片）**：闭眼、断头（头部被裁）——只做提醒，照片照常参与重复检测、重命名和绿色标签。
- **虚焦移出**：移入各自目录下的 `虚焦/` 文件夹，不参与选片。

全部推理在本地完成，照片不会上传。

## V2.0 更新

- **重复分组改成“指纹粗筛 + 像素复核”两级**：Vision 指纹只负责捞候选，是否成组由对齐后的亮度/梯度相关性决定，同一场景不同瞬间不再被并成一组。
- **参数全部外置并可重新标定**：`GroupingProfile` + `--dump-pairs` / `tools/label_pairs.py` / `tools/calibrate.py`，换活动重新标一遍即可（见“参数标定”）。
- **红标误判大幅减少**：文档/截图判定改为“高置信 + 大面积”或“文档分割 + 工具类图片”双证据；死白/死黑要求“大块裁切 + 剩余区域无细节”，夜景和逆光人像不再被误移出。
- **可选本机视觉模型复核**：`--vlm` 复核文档红标，`--vlm-pairs` 额外复核灰区照片对；运行时默认不调用任何模型。

## 检测因素与原理

### 内容相似度 / 分组

分两步判断，先粗筛再像素复核：Vision 指纹只负责“同一个场景”，能不能成组由像素级比对决定。

1. **粗筛（只看是不是候选）**
   - `Vision.GenerateImageFeaturePrintRequest` 的图像指纹，特征距离 ≤ 0.60；
   - `dHash`：64 位感知哈希，汉明距离 ≤ 6 时补进候选。
   - 同一场活动的不同瞬间（同一背景、同一队形）指纹距离也可能很小，所以这一步只用来缩小范围。
2. **像素复核（决定是否算重复）**
   - 每张照片在分析阶段缩出 96×96 亮度图、96×96 梯度图，以及 24×24 的粗对齐图（各约 9 KB）。
   - 先在 24×24 上同时搜索平移（±8 px）和缩放（1.00 / 0.97 / 0.94 / 0.91 / 0.88），再回到 96×96 做 ±3 px 细化。
   - 亮度做归一化互相关（去掉曝光和对比度差异），梯度再做一次同样对齐下的互相关。
   - 默认要求亮度相关 ≥ 0.93 且梯度相关 ≥ 0.83，两者都过才算重复。这个数字不是拍脑袋定的，见下面“参数标定”。
   - 对齐后能容纳 3% 左右的裁剪、整张缩放、二次压缩和曝光差异；`x`/`s` 人工排除照常生效。
3. **完全链接聚类**：一张照片必须与组内每一张都通过像素复核才会并入，避免不同场景被链式串联。超过 2500 张时自动改为在线聚类（只与每组代表比较），控制内存和耗时。
4. **连拍辅助**：同一子目录、文件名数字后缀连续（相差 ≤ 3）、且 EXIF 拍摄时间接近（≤ 10 秒）的照片，亮度相关要求放宽 0.03。编号/时间只是辅助证据，不会单凭编号把不同场景合并。

`--threshold` 在标定结果上下微调严格程度：0.28 是标定值（亮度需 ≥ 0.93），0.10 更严（≥ 0.957），0.60 更松（≥ 0.882）。

### 参数标定（换活动时这么做）

所有阈值都放在 `GroupingProfile`（`Sources/PicPicker/GroupingProfile.swift`）里，运行时从
`~/.config/picpicker/grouping.json` 读取，代码里没有事件相关的魔法数。换一批活动照片后重新标一遍：

```sh
# 1. 导出候选照片对的像素特征（不改动照片）
picpicker --folder ~/Pictures/2026-11 --dry-run --dump-pairs ~/cal/2026-11.tsv

# 2. 用本机视觉模型给“拿不准”的照片对打离线标签（每对正反各问一次，结论一致才记录）
python3 tools/label_pairs.py --pairs ~/cal/*.tsv --out ~/cal/labels.json --min-luma 0.86

# 3. 看不同阈值的取舍，再写出 profile
python3 tools/calibrate.py ~/cal/*.tsv --golden ~/cal/golden.tsv --labels ~/cal/labels.json --sweep
python3 tools/calibrate.py ~/cal/*.tsv --golden ~/cal/golden.tsv --labels ~/cal/labels.json \
    -o ~/.config/picpicker/grouping.json
```

- `--golden` 指向“已确认一张重复都没有”的文件夹，它的任何成组都算误合并，是最硬的一类负样本。
- 视觉模型只在这条离线流程里用；PicPicker 运行时完全不依赖它（`--vlm` 只是可选的额外复核）。
- 实测这批数据（8 个活动文件夹 + 基准文件夹，98 个正样本 / 2487 个负样本）的取舍表：

  | 亮度阈值 | 误合并 | 漏合并 |
  | --- | --- | --- |
  | 0.90 | 1 | 0 |
  | 0.93 | 0 | 0 |
  | 0.95 | 0 | 5 |
  | 0.98 | 0 | 6 |

  选 0.93 是因为它在“零误合并”的前提下保留了最多的真实重复（连拍相邻帧、同帧不同导出）。
  注意这一类数据本身是渐变的：真实连拍相邻帧 0.937–0.975，而“同一场景差几秒”也能到 0.912–0.934，
  中间地带取决于你怎么定义“同一张”，用 `--threshold` 或 profile 里的 `lumaRequirement` 调。

### 本机视觉模型（可选）

本机跑一个 OpenAI 兼容的多模态模型后，可以用 `--vlm <地址>` 让 PicPicker 多一道语义复核：

```sh
# 用 mlx_vlm 起一个本地 VL 服务（默认 127.0.0.1:8080）
python3 -m mlx_vlm.server --model ~/Models/Qwen3-VL-4B --host 127.0.0.1 --port 8080

# 复核“文档/截图”红标
picpicker --folder ~/Pictures/2026-11-11 --vlm http://127.0.0.1:8080 --vlm-model Qwen3-VL-4B --dry-run

# 再额外复核拿不准的重复候选（较慢，每对两次提问）
picpicker --folder ~/Pictures/2026-11-11 --vlm http://127.0.0.1:8080 --vlm-model Qwen3-VL-4B --vlm-pairs
```

- **文档/截图复核（开启 `--vlm` 后才启用）**：只对已经被启发式判为“文档/截图”的照片提问一次，模型回答是真实场景就撤销红标，让它照常参与选片。实测本机 Qwen3-VL-4B 在样本库上把 52 张误判里的 42 张改回真实场景，只保留了投影课件、黑板这类真正的屏幕照片。
- **重复候选复核（`--vlm-pairs`）**：只对“像素刚够阈值、或差一点没够”的照片对提问，同一对图片正反各问一次，两个方向结论一致才采纳，否则回退到像素判定。小模型在“同一场景、差一秒”的照片上结论会随图片顺序变化，所以必须两个方向一致才可信。
- 模型不可用、超时或答非所问时不会中断扫描，只是回退到像素判定，并在审阅页顶部给出提示。`--vlm-model` 省略时会先读服务端的 `/v1/models`。

### 选优评分（每组内相对比较）

- 美观：`Vision.CalculateImageAestheticsScoresRequest` 的 `overallScore`（-1…1 归一化到 0…1），并参考 `isUtility` 降低文档/截屏类图片。
- 对焦：在 2048px 灰度缩略图上计算拉普拉斯方差，取 Vision 显著性区域为主、整图为辅；组内按最大清晰度归一化，避免不同场景的绝对清晰度差异。
- 曝光：灰度直方图的亮度均值、过曝/欠曝比例、对比度。
- 人像：`Vision.DetectFaceCaptureQualityRequest` 的人脸质量，按人脸面积加权；有人脸时提高人像清晰度权重。
- 综合分：美观 45–50%、对焦 27–30%、曝光 18–20%、人像质量 10%。

### 预处理

- 高 ISO 红标：仅针对 JPG/JPEG，读取 EXIF `ISOSpeedRatings`（回退 `RecommendedExposureIndex`），大于 16000 时打红标，文件不移动、不重命名、不参与选片。
- 极端曝光红标：亮度均值与高光/阴影裁剪比例同时超限（过曝/欠曝都算）。
- 死白 / 死黑：先看画面里被渲染成 255 / 0 的面积，超过 8% 才继续判断。
  - **JPG/HEIC/PNG 等 8 位图像**：写到 255 / 0 的像素本身就没有信息，面积超限即判死白/死黑。
  - **RAW**：渲染到 255 只是色调曲线到头，不代表没有数据。对被裁切区域再用 `CIRAWFilter` 分别按 −3 EV / +3 EV 解码一次；如果该区域仍然是一片平坦（亮度标准差 < 3），才判死白/死黑，否则视为“可拉回”照常参与选片。只对裁切面积 > 3% 的 RAW 做这次额外解码，每张约多 1 秒。
  - 小面积的高光（灯光、反光、水面）和死黑（夜景暗部）不会误伤。
- 文档/截图红标：Vision 文档分割置信度高，或 `isUtility` 判定为文档/截屏类；如果画面里检测到人脸，则视为人像照片而不打红标（避免老照片带边框被误判）。
- 地平倾斜红标：`Vision.DetectHorizonRequest` 检测地平线角度，超过 35° 打红标。该 API 较保守，画面没有可靠地平线时返回空，此时不打红标（宁漏不误）。
- 闭眼黄标：人脸地标计算 **EAR**（Eye Aspect Ratio，上下眼睑距离 / 眼角水平距离），低于 `--eye-ratio`（默认 0.20）判为闭眼。
- 断头黄标：人脸框贴近画面上边缘 8% 以内判为头部被裁。
- 虚焦移出：只对“细节足够、可以判断对焦”的照片判定（亮度对比度与拉普拉斯方差达标；人脸质量良好时跳过）。阈值按**机型 + 镜头 + RAW/JPG** 分组，各取组内可用照片的方差中位数 × `--blur-ratio`（组内样本少于 8 张时退回全批中位数），并设绝对上限，避免混拍不同设备时互相误判，也避免把低细节但清晰的照片（如天空渐变）误判。用 `--global-blur` 可退回全批中位数。

### 文件与标签

- Finder 标签通过 `com.apple.metadata:_kMDItemUserTags` xattr 写入，使用系统原生红/黄/绿标签。
- 重命名只发生在每个文件**所在的子文件夹内**，跨子目录的内容重复会归入同一组，各自在本地改名；命名冲突按目录分别检测，不会覆盖已有文件。
- 虚焦照片移动到 `<所在目录>/虚焦/<原文件名>`，保留相对目录结构，同名冲突自动加 `-2` 后缀；`虚焦/` 目录在后续扫描中跳过。

## 工作流

```text
选择文件夹
   │
   ▼
递归扫描（JPEG / HEIC / PNG / TIFF / RAW，跳过隐藏文件和 .app/.lrlibrary 等包）
   │
   ▼
逐张分析（进度条 + 速度/剩余时间）
   ├─ Vision：指纹 · 美学 · 人脸质量/地标 · 显著性 · 文档分割 · 地平线
   ├─ EXIF：ISO · 拍摄时间
   └─ 像素：对焦 · 曝光 · dHash · 重复检测签名
   │
   ▼
预处理分流
   ├─ 红标（ISO / 极端曝光 / 文档截图 / 地平倾斜）── 不参与选片
   ├─ 黄标（闭眼 / 断头）────────────────── 仍参与选片
   ├─ 虚焦 ─────────────────────────────── 移入 虚焦/
   └─ 剩余照片 ───────────────────────────── 进入分组
   │
   ▼
本机视觉模型复核（可选 --vlm）
   ├─ 文档/截图红标：模型说是真实场景就撤销红标
   └─ 拿不准的重复候选（--vlm-pairs）：正反各问一次，结论一致才采纳
   │
   ▼
相似度分组（指纹粗筛 + 像素复核 + 完全链接聚类）→ 每组内选优
   │
   ▼
审阅（TUI 展示组、最佳、红/黄/绿标签计划，可调阈值）
   │
   ▼
执行（可选试运行 --dry-run / --apply）
   ├─ 每组按 组号-原文件名 重命名
   ├─ 最佳照片打绿色标签
   ├─ 红标 / 黄标写 Finder 标签
   ├─ 虚焦照片移入 虚焦/
   └─ 写入 .picpicker-undo.json（可撤销）
```

## 运行

```sh
./build.sh              # 编译 release，生成 ./picpicker，并安装到 ~/.local/bin
picpicker               # 打开 TUI，选择文件夹
picpicker --folder ~/Pictures/2026-11-11
```

需要 macOS 15 或更新版本（本机 macOS 27 已验证），以及 Xcode / Swift 6 命令行工具。

### 让终端直接输入 `picpicker`

`build.sh` 默认把可执行文件复制到 `~/.local/bin/picpicker`。该目录通常已在 `PATH` 中，新开终端后直接输入 `picpicker` 即可；当前已打开的终端如找不到命令，执行 `rehash` 或重开终端。

如果 `~/.local/bin` 不在 `PATH` 里，在 `~/.zshrc` 末尾加入：

```sh
export PATH="$HOME/.local/bin:$PATH"
```

然后 `source ~/.zshrc`。想安装到其他目录可以用 `PICPICKER_INSTALL_DIR=/usr/local/bin ./build.sh`（需要写权限）。

## 交互

| 按键 | 作用 |
| --- | --- |
| `Enter` | 选择文件夹（含子文件夹）/ 确认执行 / 结束 |
| `↑` `↓` | 切换查看的重复组 |
| `←` `→` 或 `+` `-` | 调整分组严格度（默认 0.28，范围 0.10–0.60，越小越严格） |
| `[` `]` | 把当前组的最佳照片换成上一张 / 下一张（手动指定） |
| `x` | 排除当前组的最佳照片：不再重命名、不打任何标签；组内只剩一张时整组不再参与整理 |
| `s` | 跳过整组：本组所有照片都不改名、不打标签 |
| `R` | 清除全部手动改选和排除，回到自动评分结果 |
| `v` | 在终端内查看当前组大图（真彩色半块渲染），可逐张切换 |
| `d` | 试运行：只展示计划，不修改文件 |
| `f` | 在 Finder 中显示当前组的最佳照片 / 结果文件夹 |
| `o` | 用默认看图程序打开当前组的最佳照片 |
| `c` | 复制分组结果到剪贴板 |
| `u` | 撤销上一次重命名和标签 |
| `r` | 重新扫描当前文件夹 |
| `Esc` / `Ctrl-C` | 退出 |

### 大图预览

按 `v` 进入全屏预览，图片用 24 位真彩色加半块字符（▀）渲染：每个字符格用前后景两种颜色表示上下两个像素，整块可用区域全部用于显示图片，等比缩放铺满，不留黑边。清晰度上限是终端的“列数 × 行数 × 2”个像素，比如 233×30 的窗口约 233×56；终端窗口越大，细节越多。`Terminal.app`（macOS 26 起）、`iTerm2`、`Warp`、`Ghostty` 等支持 24 位色的终端都能正常显示。

预览中的按键：

| 按键 | 作用 |
| --- | --- |
| `←` `→` / `[` `]` | 上一张 / 下一张 |
| `Enter` | 把当前这张指定为组内最佳，返回列表 |
| `x` | 排除当前这张，返回列表 |
| `v` / `Esc` | 不修改任何结果，直接返回 |

预览里的图片是实时从原图解码出的缩略图，看到的就是文件本身；切回列表后按 `o` 可以用系统看图程序看全分辨率。终端不支持真彩色时会退化为近似色，甚至可以显示成黑块，此时按 `o` 打开原图即可。

识别阶段会显示进度条、当前文件、速度与预计剩余时间：

```text
████████████████████████████░░░░░░░░░░░░  62% 8/13  DSC3347.jpg
每秒 4.2 张 · 剩余约 2 秒 · 已用 2 秒
```

**实测速度**：约 40 秒处理 500 张照片（Apple Silicon 本机、Vision 全流程并行分析 + 像素级复核），速度随照片分辨率、机型与后台负载略有浮动。其中像素复核只在分组阶段对候选照片对做，约多花 2 秒 / 500 张。

扫描时递归遍历子文件夹，重复照片即使分散在不同子目录也会归入同一组；改名只发生在各自所在的目录里。审阅页顶部会显示预处理汇总，例如：

```text
预处理 ISO>16000 红标 1 张 · 虚焦移出 1 张 · 参与选片 7 张
红标 2 张不参选 · 黄标 1 张仍参选（闭眼/断头）
```

## 命令行

```text
--folder <路径>      递归处理指定文件夹及其子文件夹（跳过选择框）
--threshold <数值>   分组严格度（越小越严格），默认 0.28
--iso-limit <数值>   JPG 高 ISO 红标阈值，默认 16000
--blur-ratio <数值>  虚焦相对阈值，默认 0.50（越小越严格）
--global-blur        关闭按机型+镜头的虚焦校准，改用全批中位数
--prefer-raw         同目录同名的 RAW+JPG 只分析 RAW，JPG 跟随 RAW 一起改名为「组号-同名」
--eye-ratio <数值>   闭眼 EAR 阈值，默认 0.20（越小越严格）
--apply              识别完成后自动执行，不再确认
--dry-run            只分析并输出计划，不修改任何文件
--json               配合 --dry-run 输出 JSON，便于脚本消费
--undo               撤销该文件夹上一次的重命名
```

示例：

```sh
# 先看计划
picpicker --folder ~/Pictures/2026-11-11 --dry-run

# 直接执行
picpicker --folder ~/Pictures/2026-11-11 --apply

# 机器可读结果
picpicker --folder ~/Pictures/2026-11-11 --dry-run --json

# 更严格的红标/虚焦/闭眼判定
picpicker --folder ~/Pictures/2026-11-11 --iso-limit 12800 --blur-ratio 0.35 --eye-ratio 0.17 --dry-run

# 更容易把同一场景的不同瞬间并成一组（仍要过像素复核）
picpicker --folder ~/Pictures/2026-11-11 --threshold 0.5 --dry-run

# 相机 RAW+JPG 同拍：只分析 RAW，JPG 跟着一起改名
```

## 安全与撤销

- 默认先展示分组结果，按 `Enter` 并确认后才修改文件；`d` 或 `--dry-run` 完全不改动文件。
- 审阅阶段的手动改选（`[` `]`）和排除（`x` `s`）只影响本次运行的计划，不会提前改动磁盘；被排除的照片不参与重命名，也不会被写入红/黄/绿标签，包括本来会被预处理红标的照片。想要恢复自动结果按 `R`。
- 重命名采用“先改临时名、再改目标名”的两段式，失败会尝试回滚。
- 执行后会在所选根文件夹写入隐藏文件 `.picpicker-undo.json`，按相对目录记录原名、新名、原始标签和移动记录；`u` 或 `--undo` 可完整还原（含红标/黄标/绿标、虚焦移动，空 `虚焦/` 目录会被清理）。
- 再次运行时若文件已是目标名字，不会重复加前缀；若出现命名冲突，会自动加 `-2`、`-3` 后缀，不覆盖已有文件。
- 撤销记录只保留最近一次有实际改动的运行；多次执行后只能撤销最后一次。

## 说明与限制

- 递归处理所选文件夹内的所有子文件夹，跳过隐藏文件和 `.app`、`.lrlibrary` 等包内容；支持 JPEG、PNG、HEIC/HEIF、TIFF、DNG、CR2/CR3、NEF、ARW 等 macOS ImageIO 能解码的格式。
- iCloud Drive 中尚未下载到本地的照片会在读取时按需下载，可能较慢。
- 在受保护目录（桌面、文稿、下载、照片图库等）运行时，终端可能需要在「系统设置 → 隐私与安全性 → 完全磁盘访问权限」中授权。
- 分组偶尔仍会有出入；先用 `d` 试运行，再用 `←` `→` 调整阈值。默认偏保守：宁可漏掉，也不把不同瞬间的照片并成一组。
- 地平倾斜依赖 Vision 的地平线检测，该 API 较保守，画面没有可靠地平线时返回空，此时不打红标（宁漏不误）。
- 闭眼基于人脸地标 EAR，低分辨率、侧脸、低头/抬头可能漏判或误判；误判只影响黄标提醒，不影响照片参与选片，可用 `--eye-ratio` 调整。断头基于人脸框贴近上边缘判断，同样可能漏判。
- `mdls` 的标签索引更新可能滞后；Finder 侧边栏和文件信息读的是同一份 xattr，写入后通常立即生效。
